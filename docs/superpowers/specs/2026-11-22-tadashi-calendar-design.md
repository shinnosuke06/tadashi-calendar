# ただしカレンダー 設計書

作成日: 2026-11-22

## 1. 目的と背景

- 父が自分で予定を入力・確認するための、**自分たちで持ち続けられるカレンダー**を作る。
- きっかけ: 既存のカレンダーアプリが急に有料化するなどして使えなくなるのが困る。
- 使う人: 父 1 人。**iPhone**、**Google アカウントあり**。予定は父が自分で入力する。
- よく使う予定: 病院・旅行など、**時刻を決めた予定**。
- 設定（Google 側の準備・iPhone への設置）は家族（このリポジトリの持ち主）が手順書を見ながら行う。

### 成功の姿

- 父がホーム画面のアイコンから開くと、**ログインなしで毎回すぐ**予定が見られ、入力・修正できる。
- 文字が大きく、入力した**予定の時刻がひと目でわかる**。
- このアプリが将来動かなくなっても、予定は Google カレンダーに残り、他のアプリで見られる。

## 2. やること（ゴール）

### 基本機能（すべて入れる）

| 機能 | 内容 |
|---|---|
| 表示 | 月・週・日・予定一覧（今日から先） |
| 予定の追加・編集・削除 | タイトル・日付・時刻・場所・メモ |
| 終日予定・複数日予定 | 旅行などを日をまたいだ帯で表示 |
| 繰り返し予定 | 毎日・毎週・毎月（同じ日／第 n 曜日）・毎年、終わり（なし／日付／回数） |
| 通知 | 予定ごとにオン・オフと時刻を選ぶ（後述） |
| 色分け | 予定の種類（病院・旅行など）ごとの色 |
| 祝日・六曜 | 日付の下に表示。六曜は設定で隠せる |
| 検索 | 言葉で予定を探す |
| 複数カレンダー | 父の Google アカウントにあるカレンダーを選んで表示 |
| 共有 | アプリ内には作らない。Google カレンダーの共有機能で行う（手順書に記載） |
| ウィジェット | アプリ内には作らない。Google カレンダーのウィジェットを使う（手順書に記載） |
| ダークモード | 色のテーマの 1 つとして用意 |

### 高機能（4 つ）

1. **よく使う予定**: 「○○眼科」などを登録しておき、選んで日付と時刻を決めるだけで入力できる。
2. **持ち物チェック**: 予定ごとのチェックリスト。「病院セット」「旅行セット」など、よく使う組み合わせを登録できる。
3. **移動時間（車）**: 自宅などから予定の場所まで、**高速ありと高速なしの両方**の所要時間を並べて表示する。
4. **天気予報**: 予定の場所（場所がなければ自宅）の、その日の天気を表示する。

### 見やすさ・使いやすさ

- **文字サイズ**を 5 段階から選べる。
- **色**: テーマ（背景と文字の色の組み合わせ）と、予定の種類ごとの色を変えられる。
- **指で広げて拡大**できる（禁止しない）。
- 入力欄をタップしたときに、iPhone が**画面を勝手に拡大しない**。
- キーボードが出ても、**入力中の文字が見える**（キーボードに隠れない）。
- **ログイン画面を一切出さない**。

## 3. やらないこと（ノンゴール）

- 家族共有のための画面、複数ユーザーへの対応（父 1 人用）
- 自作のウィジェット、日付で絵が変わるアイコン（Web アプリでは実現できない。Google カレンダーのウィジェットで代用する）
- 電車・バスの経路の自動計算（Google の仕組み上、日本ではできない。「Google マップで道を見る」ボタンで代用する）
- AI による予定の自動配置、空き時間を他人に知らせる機能
- App Store で配るアプリ（Apple への年会費がかかるため）

## 4. 絶対に避けること（アンチゴール）

これが起きたら、機能が動いていても失敗とみなす。

1. **ログインを求められて、予定が見られない・直せない。**
2. **入力した予定の時刻が、別の時刻（出発の時刻など）に書き換わる。** 予定の開始・終了時刻を変えてよいのは、父が自分で入力したときだけ。
3. 出発の時刻が、予定の時刻と見間違えるような形で表示される。
4. 文字が小さくて読めない。ボタンが小さくて押せない。
5. 電波が悪いだけで画面が真っ白になる。分かりにくい英語や技術用語のエラーが出る。
6. 有料のサービスに頼る（無料の範囲が変わると使えなくなる）。

## 5. 制約

- 対象は **iPhone の Safari で、ホーム画面に追加した Web アプリ**。iOS は最近の版を想定する。
- 費用は 0 円。使うのは GitHub Pages、Google Apps Script、Open-Meteo（天気。商用でなければ無料）。
- リポジトリは**公開されている**。コード・設定ファイル・テスト用のデータに、父の予定・住所・合言葉（設定コード）・アプリの接続先 URL を**絶対に入れない**。
- 時間帯は日本時間（Asia/Tokyo）に固定する。
- Google Apps Script の無料枠の上限（1 日あたりの呼び出し回数など）に収まるようにする。移動時間は保存時に計算して記録し、表示のたびには計算しない。
- 地図（道順・住所検索）は Apps Script に最初からある地図機能を使う。Google Maps Platform の API キーや支払いの登録はしないので、使いすぎても料金は発生しない（上限を超えるとその日は計算できないだけ）。個人の Google アカウントの上限は、道順・住所検索がそれぞれ 1 日 1,000 回（2026-11 時点の公式の割り当て表。Google は予告なく変えることがある）。アプリ側で道順は **1 日 100 回まで**に制限する。
- 天気は Open-Meteo の無料 API（API キー・登録なし、非商用の個人利用は 1 日 10,000 回・1 時間 5,000 回・1 分 600 回未満）を使う。アプリ側で **1 時間は同じ場所の予報を使い回し**、1 日 200 回までに制限する。データの決まり（CC BY 4.0）により、天気を出すところに「天気予報: Open-Meteo」と小さく出典を書く。

## 6. 作り方の候補と選んだもの

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | すべてを Google Apps Script の上で作る | 作る部品が一番少ない | ブラウザの Google ログインが切れると止まる。Google の枠の中で表示されるため、iPhone で拡大やキーボードの調整がしにくい。電波がないと何も出ない |
| **B（採用）** | **画面は自作の Web アプリ、Google とのやりとりだけ Apps Script に任せる** | **父のログインが一切不要**。画面を思い通りに作れる。電波がなくても最近の予定が見られる | 最初に一度だけ設定が必要（手順書で対応）。合言葉が漏れると予定を見られる |
| C | Web アプリから直接 Google にログインして連携 | よくある作り方 | 1 時間ごとに確認画面が出やすく、アンチゴール 1 に反する |
| D | スマホの中だけに保存 | ログイン不要で一番簡単 | 機種変更などで消える。Google の通知が使えない |

**B を選んだ理由**: 「ログインで止まって使わなくなる」を一番確実に防げて、文字サイズ・拡大・キーボードの要望も満たせる。家族は「手順書があれば設定できる」と確認済み。

## 7. 全体の仕組み（決まったこと）

```
[父の iPhone]                         [Google（父のアカウント）]
 ホーム画面の Web アプリ  ──合言葉付きで依頼──▶  Apps Script（父のアカウントとして動く）
  ・画面（GitHub Pages に置く）                  ├─ Google カレンダー（予定の正本）
  ・最近の予定を端末に保存                       ├─ 地図機能（移動時間・住所→緯度経度）
  ・送れなかった変更を一時保存                   └─ スプレッドシート（毎晩の控え・設定）
        │
        └──天気──▶ Open-Meteo（無料の天気予報）

 Google カレンダーのアプリ … 通知を出す／ウィジェットを表示
```

### 7.1 データの置き場所

- **予定の正本は Google カレンダーだけ**（父のメインのカレンダー）。新しい予定もここに入れる。
- **毎晩自動で**、Google カレンダーの予定を**スプレッドシートに丸ごとコピー（控え）**する。控えは何日分か残し、古いものは消す。控えは一方通行のコピーなので、中身がずれても不具合は起きない。
- 控えから予定を戻せるようにする。スプレッドシートで行を選んでメニューから「この予定を戻す」を押す。家族向けの操作として手順書に書く。
- Google カレンダー自体のゴミ箱（消した予定が 30 日間残る）も、手順書で案内する。
- 予定に付ける情報（持ち物・移動時間・緯度経度・種類）は、**その予定の中に**記録する（Google カレンダーの、予定ごとに隠れた情報を持てる欄を使う）。持ち物は、Google カレンダーのアプリでも見えるよう、メモ欄の最後にも文字で書き出す。
- よく使う予定・持ち物セット・自宅住所・表示の設定は、Google 側（スプレッドシート）に保存する。機種変更や入れ直しのあとも元に戻る。端末にも同じものを持ち、開いた瞬間から設定が効くようにする。

### 7.2 ログインなしの仕組み

- Apps Script を「父のアカウントとして動く Web アプリ」として公開する。誰でも呼べる状態になるので、**合言葉（推測できない長いランダムな文字列）を持つ依頼だけ**を受け付ける。
- 合言葉と接続先は、家族が初回設定のときに、iPhone のホーム画面アプリへ「設定コード」として貼り付ける。合言葉は URL に含めず、依頼の本文で送る。
- 合言葉は作り直せる（スマホを失くしたときなど）。作り直すと古い合言葉は使えなくなる。
- 接続の設定は「家族向けの設定」の奥に置き、父が誤って触らないようにする。
- 設定が消えて接続できないとき（めったにない）は、大きな文字で「家族に連絡してください」と出す。

### 7.3 電波がないとき・失敗したとき

- 開いたら、まず端末に保存してある予定をすぐ表示し、そのあと Google から最新を取り直す。
- 保存（追加・修正・削除）が送れなかったときは端末に一時保存し、電波が戻ったら自動で送り直す。送れていない予定には「まだ保存中」と分かる印を付ける。
- エラーの表示は、短い日本語にする。例: 「電波が弱いので、あとで自動で保存します」。英語やコード番号は出さない。
- 父が Google カレンダーのアプリで直接直した予定も、次に開いたときに反映される。

## 8. 予定の時刻と出発の目安（重要）

- 予定の**開始・終了の時刻は、父が入力したものだけ**を使う。移動時間の計算や通知の設定で、時刻を変えることは一切しない。
- 出発の時刻は、あくまで**「出発の目安」**として、予定の時刻とは別の場所に表示する。
  - 出発の目安 ＝ 予定の開始時刻 − 移動時間 − 余裕の時間（初期値 10 分、設定で変更可）。5 分単位で早めに丸める。
  - 高速あり・高速なしの**両方**を並べて表示する。
  - 一覧・月・週・日の画面では、**予定の時刻を一番目立つ形**（太字、タイトルと同じかそれ以上の大きさ）で出す。出発の目安は、それより小さい文字で、「目安」という言葉を付けて別の行に出す。予定の時刻と同じ列には出さない。
  - 詳しい画面では「10:00 に間に合う出発の目安」のように、予定の時刻とのつながりが分かる書き方にする。
- 通知の選択肢に「出発の目安の時刻」を入れる（初期状態では選ばない）。これは通知を鳴らす時刻であって、予定の時刻ではない。Google カレンダーの通知には予定の時刻（10:00）が表示される。

## 9. 各機能の詳しい動き

### 9.1 予定の入力

- 入力画面の一番上に「よく使う予定」のボタンを並べる。押すと、タイトル・種類・場所・長さ・持ち物・通知がまとめて入る。
- 入力する項目: タイトル、日付、終日かどうか、開始時刻・終了時刻、複数日（終わりの日）、場所、種類（色）、繰り返し、通知、持ち物、メモ、出発する場所（初期値は自宅。旅行先のホテルなど、別の住所も選べる）。
- 日付と時刻は iPhone 標準の選び方（くるくる回す画面）を使う。選んだ値は大きな文字で表示する。
- 終了時刻の初期値は「開始時刻 ＋ よく使う予定の長さ（なければ 1 時間）」。一覧では開始時刻を大きく、終了時刻は小さく出す。
- 繰り返す予定を直すときや消すときは、「この予定だけ」「これ以降すべて」「すべて」から選ぶ。
- 保存ボタンは、入力画面の上と下の両方に置く。
- 消すときは、大きなボタンで「本当に消しますか？」と確認する。

### 9.2 通知

- 予定ごとにオン・オフを切り替えられる。オンのときは次から最大 5 つ選べる: 1 週間前・2 日前・前日（同じ時刻）・3 時間前・1 時間前・30 分前・出発の目安の時刻。
- 終日の予定では「前日の夜 ○時」「当日の朝 ○時」の形で選ぶ。
- 新しい予定の初期値は「オン（前日・1 時間前）」。よく使う予定ごとに初期値を変えられる。
- オフのときは、Google カレンダー側の「いつもの通知」も付かないようにする（通知なしを明示的に記録する）。
- 通知は **Google カレンダーのアプリ**が出す。アプリが入っていて通知が許可されているかは、設置のときに手順書で確認する。iPhone 標準のカレンダーにも Google の予定を同期していると通知が二重になることがあるので、どちらか一方にするよう手順書に書く。

### 9.3 持ち物チェック

- 予定ごとに、持ち物の一覧と、それぞれのチェック状態を持つ。チェックは大きな四角で、押しやすくする。
- 「病院セット」（初期値: 保険証・診察券・お薬手帳・お金）、「旅行セット」などの持ち物セットを、設定で追加・編集できる。
- 予定に記録できる情報の量には上限がある。持ち物が多い場合も記録できるよう、作るときに工夫する。

### 9.4 移動時間（車）

- 予定を保存するときに場所が入っていれば、出発する場所（初期値は自宅）からの所要時間を、**高速あり・高速なしの 2 通り**で計算して予定に記録する。計算には Apps Script の地図機能を使い、費用はかからない。1 回の計算で道順を 2 回（高速あり・なし）使う。場所を入れていない予定は計算しない（出発の目安も出さない）。
- 計算に使った住所を「○○市○○町…として計算しました」と表示し、場所の取り違えに気づけるようにする。施設名で見つからないときは、住所を入れてもらうよう案内する。よく使う予定には正確な住所を登録しておく。
- 渋滞は考慮しない、おおよその時間であることを小さく書き添える。
- 「計算し直す」ボタンと、「Google マップで道を見る」ボタン（車・電車を Google マップのアプリで開く）を付ける。
- 複数日の予定では、1 日目の行きだけを計算する。

### 9.5 天気予報

- 場所が入っている予定は、保存時に緯度・経度を調べて記録し、Open-Meteo からその日の天気を取ってくる。場所がなければ自宅の天気を使う。
- 表示する内容: 天気のマーク（晴れ・くもり・雨・雪）と日本語、最高・最低気温、降水確率。時刻のある予定は、その時間帯の降水確率も出す。
- 予報が出るのはおよそ 2 週間先まで。それより先の予定には「近くなったら表示されます」と出す。
- 天気を出すところには「天気予報: Open-Meteo」と小さく出典を書く。
- 一覧の画面の上に「今日の天気（自宅）」を出す。

### 9.6 表示の画面

見た目と操作は、父が今使っている「シンプルカレンダー」の並びに寄せる（家族の希望）。ただし、そのアプリのアイコン・名前・絵柄はまねしない。見本: https://claude.ai/artifact/NfJsaR2UaeVQVKe3np77VE（家族と父が確かめて「いい感じ」とのこと）

**月の画面（最初に開く画面）**
- 画面の上に「2026年 **11月**」（年は小さく、月は大きく）と、「🔍 探す」「⚙ 設定」のボタン。その下に曜日の行（日曜は赤、土曜は青）。
- **月の表は画面いっぱい**に出す（6 週分の高さ）。予定の一覧を常に下に出すことはしない。
- 月の表は、**週を縦に途切れずつなげた一続きの表**にする。上下にスクロールでき、週の区切りで止まる。**同じ日付は 1 回だけ**出す（月ごとに別の表を作って、前後の月の日を重ねて出すことはしない）。
- 見えている週から「今の月」を決めて上に出し、その月以外の日は薄い背景と薄い文字にする。各月の 1 日には「12月」のような小さな印を付ける。
- マスの中（上から）:
  - 1 行目: 日付の数字（土曜は青、日曜・祝日は赤、今日は背景を黄色）。**日付は必ず先に出し、文字を大きくしても切れたり押し出されたりしない**。あふれるのは予定の名前のほう。
  - 2 行目: 六曜と祝日名（六曜を出す設定のとき）。六曜を出さない設定のときは、この行を作らず、祝日名は日付の数字の右に小さく出す。
  - 予定の名前: 種類の色の小さな札で、最大 3 つ。それ以上は「+n」。設定で「色の点だけ」にも切り替えられる。
  - 何日も続く予定（旅行など）は、**マスの区切り線の上でつながる 1 本の帯**にする。名前は始まりの日と、週の最初の日にだけ出す。帯は週ごとに段を決め、どの日でも同じ高さにそろえる（重なっても段がずれない）。
- マスの中の文字は、文字サイズを大きくしても上限を設ける（日付は最大 28px、予定の名前は最大 15px）。マスの幅に限りがあるため。大きな文字で読むのは、下から出る予定の一覧と、詳しい画面で行う。
- **日付を押すと、その日の予定が下からせり上がってくる**（画面の約 6 割の高さ）。押した日の週は予定に隠れないよう、表が必要な分だけ動く。予定が出ている間に別の日を押すと切り替わる。閉じる方法は「閉じる」ボタン、上の部分を下へなぞる、同じ日をもう一度押す、の 3 つ。
- 下から出る予定の中身: 見出し（日付・今日・六曜・祝日・天気）、予定の行、「＋ この日に予定を追加」。予定の行は、左に時刻（始まりを大きく太く、終わりはその下に小さく。終日なら「終日」）、色の帯、タイトル、その下に小さく出発の目安。
- 画面の下のボタン: 「今日」「月」「週」「日」「一覧」と、右端に丸い「＋ 追加」。「今日」は今月の表に戻り、今日の予定を下から出す。

**そのほかの画面**
- 週: 文字が大きいと横に 7 列は読めないため、**7 日を縦に並べる**。「◀ 前の週」「今週」「次の週 ▶」。
- 日: 時間の目盛りに沿って予定を並べる。「◀ 前の日」「今日」「次の日 ▶」。
- 一覧: 一番上に「今日の天気（自宅）」、その下に今日から先の予定を日付ごとに並べる。
- 予定を押すと詳しい画面が開き、時刻・タイトル・場所・移動の目安・天気・持ち物・通知・メモを見られる。

### 9.7 文字サイズと色

- 文字サイズは 5 段階（目安: 16・18・22・26・32px）。設定画面で、見本を見ながら選べる。
- 月の表のマスの中の文字だけは、9.6 のとおり大きさに上限を設ける（マスの幅に限りがあるため）。
- どの段階でも、**入力欄の文字は 16px より小さくしない**。iPhone は 16px 未満の入力欄をタップすると画面を拡大するため。
- どの段階でも、時刻が「…」で切れない。タイトルは折り返す。ボタンは文字に合わせて大きくなる（最小でも指で押しやすい大きさ）。
- 色のテーマを用意する: 白（標準）・さくら（ピンク）・わかば（緑）・クリーム（目にやさしい）・黒地に白（ダーク）・くっきり（高コントラスト）。どのテーマでも、文字と背景の差を十分に大きくする。
- 予定の種類の色は、Google カレンダーと同じ 11 色から選ぶ。Google カレンダーのアプリやウィジェットでも同じ色で見える。
- 種類の初期値: 病院・旅行・家族・用事・その他。名前と色は設定で変えられる。
- 読みやすさを重視した文字の形（UD フォント）を選べるようにする。フォントのファイルはアプリと一緒に置き、外部の配信には頼らない。

### 9.8 拡大とキーボード

- 指で広げて拡大する操作を禁止しない。
- 入力画面は、上下にスクロールできる普通のページにする。画面の下に固定した入力欄は作らない。
- 入力中は、画面の下のボタンの並びを隠す。入力欄がキーボードに隠れないよう、入力欄がキーボードの上に見えるところまで画面を動かす。
- 最終確認は、父の iPhone（実機）で家族が行う。確認項目は手順書に載せる。

### 9.9 設定画面

- 父が触る項目: 文字の大きさ、色のテーマ、予定の種類と色、最初に開く画面、週の始まり（日曜または月曜）、六曜の表示、月の表に予定の名前を出すか（切ると色の点）、表示するカレンダー、よく使う予定、持ち物セット、余裕の時間、出発の目安の通知に使う道（高速なし を初期値。早めの時刻になるため）。
- 家族向けの設定（奥に置く）: 自宅の住所、接続の設定コード、作りの番号（アプリと Google 側の版）。

## 10. 手順書（家族向け、一緒に作る）

1. Google 側の準備（パソコン推奨）: 父のアカウントで Apps Script を作る → コードを貼る → 必要な機能を有効にする → 初回の許可（「Google で確認されていません」の画面の進み方も説明する）→ Web アプリとして公開 → 毎晩の控えを有効にする → 設定コードを控える。
2. iPhone: Safari でアプリの URL を開き、ホーム画面に追加する。
3. **ホーム画面のアイコンから**開き、設定コードを貼り付ける。Safari で開いたままだと保存場所が別になるため、必ずアイコンから開く。
4. Google カレンダーのアプリが入っているか確認する。通知を許可する。ウィジェットをホーム画面に置く。
5. 自宅の住所、文字の大きさ、色を設定する。
6. 今のアプリからの予定の引っ越し（13 章）。
7. 実機での確認項目（キーボード・拡大・通知・電波のないところでの表示）。
8. 困ったとき: 合言葉の作り直し、アプリの更新のしかた（Google 側の作り直しを含む）、消した予定の戻し方。

## 11. 作る人に任せること

- 使う道具（フレームワーク、ビルドの有無、言語）、ファイルの構成、Apps Script との通信の形式。
- 祝日・六曜の計算方法（外部のデータに頼らず、アプリの中で計算するか、データを同梱する）。計算結果は、信頼できる暦と何日か照らし合わせて確かめる。
- テーマごとの具体的な色の値（文字と背景の差の基準は満たす）、アイコンの絵柄。
- 端末に保存する範囲と、Google から取り直す頻度。
- 控えを何日分残すか。
- アプリと Google 側の版が合わないときの扱い（家族に「Google 側の更新が必要」と知らせる）。
- テスト: 日付の計算・出発の目安・繰り返し・天気の表示などは自動テストで確かめる。画面は iPhone の大きさを再現したブラウザで確かめる。Apps Script の部分は、Google の機能を模した偽物で確かめる。最後は実機で確かめる。
- 電波が戻って送り直すときに、同じ予定が Google カレンダーのアプリでも直されていた場合の扱い（父 1 人で使うため、後から保存したほうを残す）。
- GitHub Pages で公開する方法（どのブランチから出すか）。家族がリポジトリの設定で行う操作があれば、手順書に入れる。

## 13. 今のアプリからの引っ越し（決定）

- 父が今使っているのは、iPhone の「シンプルカレンダー - スケジュール帳、予定表」（前に使っていたアプリが有料になったため乗り換えた）。App Store の説明によると iCloud・Google・Microsoft のカレンダーに対応しているので、予定はアプリの中ではなく、iPhone のカレンダー（iCloud・Google・この iPhone のどれか）に入っている可能性が高い。実際にどこに入っているかは、設置のときに下の手順 2 で確かめる。
- 予定が父の Google カレンダーに入っていれば、慣れるまでの間は**シンプルカレンダーと新しいアプリの両方で同じ予定が見える**。そのため、乗り換えを急がなくてよい。ただし、両方のアプリが通知を出すと二重になるので、手順書で片方の通知を切るよう案内する。
- 書き出す機能はなさそうなので、**取り込み機能は作らない**。手順書に「引っ越し」の章を入れる。
- 父が見慣れている画面の並び（月の表の中に予定の名前と六曜、下に「月・週・日」、＋ボタン）に寄せた。決めた形は 9.6 のとおり。
- 引っ越すのは**これから先の予定だけ**にする。病院の予約や旅行など、数は多くない見込み。過去の予定は今のアプリに残しておく。
- 手順書の流れ（家族が設置のときに確かめる）:
  1. 父の iPhone で、今使っているアプリの名前を確かめる。
  2. iPhone の標準の「カレンダー」アプリに、同じ予定が出ているか確かめる。
     - 出ていて、Google のカレンダーに入っている場合: すでに Google にあるので、引っ越しは不要。
     - 出ていて、iCloud や「この iPhone」のカレンダーに入っている場合: 標準のカレンダーアプリで予定を開き、「カレンダー」の欄を父の Google のカレンダーに変えて移す。
     - 出ていない場合: 今のアプリが独自に予定を保存している。新しいアプリで、先の予定を入れ直す（よく使う予定を先に登録しておくと早い）。
  3. 引っ越しが終わり、新しいアプリに慣れるまでは、今のアプリを消さずに残す。
